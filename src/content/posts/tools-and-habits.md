## 先分清两件事

很多人把「工具」和「习惯」混为一谈，结果两边都做不好。

- **工具**解决的是「能不能做」。没装编辑器，你写不了代码。
- **习惯**解决的是「会不会做」。装了编辑器但从不打开，等于没装。

单独优化任何一边都没用。买了一堆效率软件却依然拖延的人，问题从来不在软件。

## 工具：少而熟

我的原则是**工具数量要少到能记住，熟练到不用想**。

判断一个工具该不该留，我看三条：

1. 一周内用过吗？
2. 用的时候需要查文档吗？
3. 如果它消失，我会难受吗？

三条里否定两条的，就删掉。这个标准很粗暴，但清理效果很好。

### 关于键盘

值得投资的只有一件事：**让你少碰鼠标**。

把手放回键盘中间的那半秒钟，看着不起眼，一天累积下来是几百次上下文切换。改键位、学快捷键、用模糊搜索，回报都在这上面。

```bash
# 把重复的动作交给 shell，别每次都完整敲一遍
alias gs='git status -sb'
alias ll='ls -lah'
alias ..='cd ..'

# 模糊查找：少记路径，多敲几个字母
# fd / fzf / rg 都是这个思路的产物
```

## 习惯：把决策变成默认

习惯的本质是**把需要意志力的决策，提前变成不需要思考的默认**。

举几个我实际在用的：

### 两分钟规则

一件事如果两分钟内能做完，就立刻做，不要记进待办。

记进待办的成本（写下来、之后再看、再判断）往往比事情本身还高。

### 固定的启动动作

写东西之前，我会先做同一件事：打开文件，写下标题，然后写一句「这篇要说什么」。

不追求写得好，只追求**把空文件的恐惧感消掉**。人一旦开始，惯性就会接管。

### 允许中断，但留记号

写不下去的时候不硬扛，但在离开前一定写一行注释，告诉未来的自己「刚才想到哪了」。

下次坐下来的启动成本会低很多。

## 一个简单的时间分配

```text
每天
├── 深度工作  2 小时   ← 最难的事放这里
├── 常规事务  3 小时   ← 邮件、沟通、杂活
└── 学习输入  1 小时   ← 读书、看论文、试新工具
```

这个结构不是用来「填满」的，而是用来**决定什么时候不做什么**。早上那两个小时不开消息通知，是整张表里最重要的一行。

## 别追求完美系统

最后一个提醒，也是我踩过的坑：

**不要花时间设计一套完美的系统，然后指望它自动运转。**

系统是用来被消耗的，不是用来被欣赏的。真正跑起来的粗糙系统，永远胜过躺在文档里的精美系统。

先跑起来，再慢慢修。
